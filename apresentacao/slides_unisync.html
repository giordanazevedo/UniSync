1. Introdução e Contexto · 1 min

O Problema Real & O Desafio de Performance

Por que criamos o UniSync e quais gargalos precisamos eliminar desde a arquitetura.

1 O Problema do Estudante

  • Horários de aula, anotações por matéria, tarefas recorrentes, faltas e gastos ficam espalhados em vários apps.
  • Apps puramente locais fazem o aluno perder todos os dados ao trocar de celular.
  • Falta um lembrete simples (Sim / Não) no celular que contabilize automaticamente quantas vezes uma rotina ocorreu no mês.

⚡ Principais Desafios de Performance

  • Falta de conexão / latência de rede: não travar a interface ao salvar anotações, tarefas ou gastos.
  • Bateria em segundo plano: disparar notificações recorrentes sem polling nem timers na CPU.
  • Fluidez da UI (60 FPS): calendário mensal, listas e gráficos leves sem jank nem memory leaks.

4. Mergulho Técnico (1/3) · Rede & Offline-First

Otimização 1: Cache Offline-First & Sync Assíncrono

Como zeramos a latência percebida na Main Thread e reduzimos chamadas de rede.

☁ Estratégia Aplicada

  • Write-Local First: toda alteração grava imediatamente no cache local (SharedPreferences isolado por e-mail).
  • Background Sync não-bloqueante: unawaited(pushToCloud()) envia para o Supabase sem congelar a UI.
  • Payload consolidado (JSONB): 1 única tabela user_app_data protegida por RLS — ao trocar de celular, 1 única query restaura toda a conta (em vez de 6+ requisições encadeadas).

Trecho Real — storage_service.dart

static Future<void> saveFixedTasks(List<FixedTask> tasks) async {
  final prefs = await SharedPreferences.getInstance();
  await prefs.setString(
    _key(prefs, _fixedTasksKey),
    jsonEncode(tasks.map((t) => t.toJson()).toList()),
  );
  _syncInBackground(); // Não bloqueia a UI Thread
}

static void _syncInBackground() {
  if (!isCloudConnected) return;
  unawaited(pushToCloud()); // Upsert único no Supabase
}

4. Mergulho Técnico (2/3) · Memória, CPU e Bateria

Otimização 2: Memória, CPU & Notificações sem Dreno

Prevenção de memory leaks, correção de loop infinito na CPU e delegação ao SO.

⚡ Controle de Recursos

  • Zero Memory Leaks: descarte explícito (dispose()) de todos os TextEditingController e StreamSubscription (notificações e sessão Auth) + checagem if (!mounted) return pós-await.
  • Zero Polling em Background: notificações delegadas ao AlarmManager do Android (zonedSchedule + BootReceiver) — app fechado consome 0% de CPU.
  • Bug Crítico Corrigido: loop infinito no cálculo da próxima notificação (quando hora atual > hora agendada) reescrito para O(1) (máx. 7 iterações).

Correção de CPU — notification_service.dart

// ANTES: avançava dias mantendo a hora atual → LOOP INFINITO!
// DEPOIS: O(1) — no máximo 7 passos garantidos
tz.TZDateTime _nextInstanceOfWeekdayAndTime(
  int weekday, int hour, int minute,
) {
  final now = tz.TZDateTime.now(tz.local);
  var scheduled = tz.TZDateTime(
    tz.local, now.year, now.month, now.day, hour, minute,
  );
  while (scheduled.weekday != weekday || !scheduled.isAfter(now)) {
    scheduled = scheduled.add(const Duration(days: 1));
  }
  return scheduled;
}
